    Database Agent

    The Database Agent serves as the single source of truth for all job tracking data and the primary interface between the orchestrator and the SQLite database. It handles all database operations and provides structured responses to orchestrator queries.

    🏗️ Architecture Overview

    Orchestrator → Database Agent → SQLite Database (linkedin_jobs.db)
                    ↓
            Other agents receive 
            database state info

    The Database Agent follows a strict pattern where: - Only it can directly interact with the database - Other agents request data through the orchestrator - All database operations are atomic and validated

    📁 Directory Structure

    database_agent/
├── __init__.py     # Exports database_agent
├── agent.py        # LlmAgent definition
├── prompt.py       # Agent instructions
├── readme.md       # This file
└── tests/          # Empty - tests are in tools/tests/

    🔧 Core Responsibilities

    1. Database Management

    • Initialize database schema when needed
    • Maintain data integrity and consistency
    • Handle all CRUD operations

    2. Job Lifecycle Tracking

    • Track jobs through status pipeline: 
      Placeholder → Pending Review → Ready To Apply → Applied/Not a Fit
    • Manage job metadata and application history
    • Prevent duplicate applications

    3. Orchestrator Liaison

    • Translate natural language requests to database operations
    • Provide structured status reports
    • Suggest next actions based on database state

    🛠️ Available Tools

    Job Management

    • create_db_and_tables() - Initialize database schema
    • add_job(job_data) - Add new job to database
    • update_job_status(job_id, status) - Update job status
    • get_job_details(job_id) - Get complete job information
    • get_jobs_by_status(status) - Retrieve jobs by status

    Duplicate Prevention

    • get_applied_urls_by_role_type_with_filters() - Get URLs already applied to
    • get_available_placeholders() - Find unused placeholder jobs

    Placeholder System

    • prefill_job_placeholders() - Create placeholder jobs for search
    • update_placeholder_with_real_job() - Convert placeholder to real job
    • purge_old_placeholders() - Clean up old unused placeholders

    💬 Orchestrator Communication Patterns

    Status Queries

    Orchestrator: "What's the current status?"
Database Agent: Uses get_jobs_by_status() to provide:
- X jobs in Pending Review
- Y jobs Ready To Apply  
- Z jobs Applied
- Suggested next action

    Update Requests

    Orchestrator: "Update job 123 to Applied"
Database Agent: 
- Validates status transition
- Updates database
- Confirms: "Job 123 updated to Applied"

    Duplicate Checking

    Orchestrator: "Did we apply to Google for Python Developer?"
Database Agent:
- Checks applied URLs with filters
- Returns: "Yes, applied on 2024-01-15" or "No matching application found"

    📊 Database Schema

    Jobs Table

    • id - Primary key
    • company_name - Company name
    • job_title - Position title
    • job_url - Application URL
    • job_description - Full description
    • application_status - Current status
    • role_type - engineer/product
    • drive_folder_id - Google Drive folder
    • resume_link - Resume document URL
    • cover_letter_link - Cover letter URL
    • Plus timestamps and metadata

    Valid Statuses

    • Placeholder - Pre-filled for search
    • Pending Review - Scraped, needs processing
    • Ready To Apply - Has documents, ready
    • Applied - Application submitted
    • Not a Fit - Rejected by content generator
    • Error - Application failed
    • Application in Progress - Currently being processed

    🧪 Testing

    Database functions are extensively tested in: - tools/tests/test_database_application_functions.py - tools/tests/test_database_folder_operations.py - tools/tests/test_db_tools.py

    Run tests: 

    pytest orchestrator_agent/tools/tests/test_database*.py -v

    🔍 Debugging

    Enable SQL logging: 

    import logging
logging.getLogger('orchestrator_agent.tools.database').setLevel(logging.DEBUG)

    Common queries: 

    -- Check job counts by status
SELECT application_status, COUNT(*) FROM jobs GROUP BY application_status;

-- Find stuck jobs
SELECT * FROM jobs WHERE application_status = 'Application in Progress' 
AND updated_at < datetime('now', '-1 hour');

-- Check for duplicates
SELECT company_name, job_title, COUNT(*) as count 
FROM jobs GROUP BY company_name, job_title 
HAVING count > 1;

    🚨 Important Notes

    1. Single Source of Truth: Only the Database Agent can modify the database
    2. Status Validation: Invalid status transitions are rejected
    3. Atomic Operations: All updates are transactional
    4. No Direct Access: Other agents must go through orchestrator
    5. Data Integrity: Foreign keys and constraints are enforced

    🔗 Dependencies

    • SQLite3 - Database engine
    • Google ADK - Agent framework
    • Python datetime - Timestamp handling
