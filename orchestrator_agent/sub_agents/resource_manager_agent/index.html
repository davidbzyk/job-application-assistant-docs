    Resource Manager Agent

    This module handles the creation of Google Drive folders and copying of role-specific resumes for job applications.

    Overview

    The Resource Manager is responsible for: - Creating company-specific folders in Google Drive - Copying the appropriate resume (engineer vs product) based on job role - Converting documents to PDF format - Updating the database with folder and document links

    Components

    1. Regular Resource Manager (agent.py)

    • Use case: Processing ≤50 jobs
    • Agent type: LlmAgent
    • Processes: Jobs one at a time with natural conversation flow
    • Status flow: Jobs remain in "Pending Review" after processing

    2. Batch Resource Manager (batch_resource_manager.py)

    • Use case: Processing >50 jobs
    • Agent type: BaseAgent with internal LlmAgent worker
    • Batch size: 50 jobs per batch
    • Rate limiting: 60-second cooldown between batches
    • Error handling: Extended 90-second cooldown on Google Drive API rate limits

    3. Junior Resource Manager (agent.py)

    • Use case: Simplified version optimized for Gemini 2.0
    • Features: Also handles cleanup of rejected job folders

    Usage

    The orchestrator automatically selects the appropriate resource manager:

    User: "resource"
→ Orchestrator calls get_jobs_needing_resources()
→ If ≤50 jobs: Uses resource_manager_agent
→ If >50 jobs: Uses batch_resource_manager

    Workflow

    1. Job Detection: Find jobs with status "Pending Review" that lack resume links
    2. Folder Creation: Create a Google Drive folder named "{Company} - {Job Title}"
    3. Resume Selection: Determine role type (engineer/product) and get appropriate resume
    4. Document Copying: Copy resume to company folder with applicant name
    5. PDF Conversion: Convert Google Docs to PDF format
    6. Database Update: Save folder ID, resume links, and PDF links

    Key Features

    Smart Batch Processing

    • Processes large job queues without hitting API rate limits
    • Automatic retry with extended cooldowns on rate limit errors
    • Progress tracking and reporting between batches

    Role-Based Resume Selection

    • Automatically detects job role type from job title
    • Selects appropriate resume folder based on role
    • Falls back to engineer resume as default

    State Management

    • Uses ADK memory functions (memorize/recall_all) for session state
    • Shares state between orchestrator and sub-agents
    • Batch context passed via session state

    Important Notes

    1. Memory Functions: Never wrap memorize or recall_all in FunctionTool (causes ADK errors)
    2. Status Updates: Jobs stay in "Pending Review" after resource processing
    3. Content Generator Dependency: Content generator expects jobs to have resume links before processing
    4. Rate Limits: Google Drive API has quotas - batch processor handles this automatically

    Error Handling

    • Missing resume folders: Falls back to engineer resume
    • API rate limits: Automatic cooldown and retry
    • Failed folder creation: Job remains unprocessed for next batch
    • Database errors: Transaction rollback to maintain consistency
