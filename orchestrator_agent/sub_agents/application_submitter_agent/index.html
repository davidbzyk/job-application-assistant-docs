    Application Submitter Agent

    The Application Submitter Agent is responsible for automatically submitting job applications on LinkedIn and Google Jobs using Browser Use automation. It processes jobs marked as "Ready To Apply" in the database using a subprocess-based approach that ensures complete Chrome isolation between jobs to prevent 429 rate limiting errors.

    🏗️ Architecture Overview

    Orchestrator Agent
    └── Batch Submitter Agent (orchestration layer)
            ├── linkedin_submitter.py (subprocess execution)
            │       ├── Chrome Process Management (fresh instance per job)
            │       ├── Browser Use CDP Connection
            │       ├── Controller Actions (file uploads, Gmail verification)
            │       └── Database Updates
            └── google_submitter.py (subprocess execution)
                    ├── Chrome Process Management (fresh instance per job)
                    ├── Browser Use CDP Connection
                    ├── Controller Actions (file uploads, navigation)
                    └── Database Updates

    Key Change: Subprocess Isolation

    Each job runs in a completely separate Python process, ensuring: - Chrome fully terminates between jobs (prevents context pollution) - Fresh browser state for each application (avoids 429 errors) - Exact replication of test script behavior - Clean memory and connection state

    🔄 Application Workflow

    Subprocess Execution Model

    batch_submitter.py → subprocess.run() → linkedin_submitter.py <job_id>
                                    └──→ google_submitter.py <job_id>

    1. Batch Processing

    • Batch Submitter fetches jobs with "Ready To Apply" status
    • Routes jobs to appropriate submitter based on submitter_tool field
    • Processes one job at a time with 30-second cooldowns
    • Each job runs in isolated subprocess

    2. Subprocess Execution

    # Run appropriate submitter based on job source
if job['submitter_tool'] == 'linkedin_submitter':
    subprocess.run([python_path, "linkedin_submitter.py", str(job_id)])
elif job['submitter_tool'] == 'google_submitter':
    subprocess.run([python_path, "google_submitter.py", str(job_id)])

    3. Chrome Lifecycle (Per Job)

    1. Start fresh Chrome instance with Browser Use profile
    2. Connect via CDP on port 9222
    3. Execute job submission
    4. Terminate Chrome completely (pkill)
    5. Exit subprocess cleanly

    4. Browser Automation Flow

    LinkedIn Submitter:

    • Downloads resume/cover letter from Google Drive
    • Connects to Chrome via CDP
    • Navigates to LinkedIn job URL
    • Handles multi-step Easy Apply process
    • Uploads documents and fills forms
    • Submits application

    Google Jobs Submitter:

    • Downloads resume/cover letter from Google Drive
    • Connects to Chrome via CDP
    • Navigates to Google Jobs URL
    • Extracts and follows Apply button to company site
    • Handles various application portals (Greenhouse, Lever, etc.)
    • Uploads documents and fills forms
    • Submits application

    5. Controller Actions

    Shared browser actions (in browser_actions/shared_browser_actions.py): - Resume/cover letter content extraction (PDF support) - File uploads to application forms - Gmail verification code/URL retrieval - Database status updates - Personal information provision - Apply button detection and clicking - Navigation to application URLs - CAPTCHA handling with 2captcha integration

    6. Status Updates

    Ready To Apply → Application in Progress → Applied/Error/Not a Fit

    🛠️ Key Components

    Batch Submitter (batch_submitter.py)

    • ADK BaseAgent that orchestrates job processing
    • Runs each job as isolated subprocess
    • 30-second cooldowns between jobs
    • Handles subprocess communication via JSON
    • Tracks success/failure statistics

    LinkedIn Submitter (tools/linkedin_submitter.py)

    Standalone script that: 1. Takes job ID as command line argument 2. Fetches job data from database 3. Downloads resume/cover letter from Google Drive 4. Starts Chrome with Browser Use profile 5. Connects via CDP (Chrome DevTools Protocol) 6. Runs Browser Use agent for LinkedIn Easy Apply 7. Terminates Chrome completely 8. Returns JSON result via stdout

    Google Submitter (tools/google_submitter.py)

    Standalone script that: 1. Takes job ID as command line argument 2. Fetches job data from database 3. Downloads resume/cover letter from Google Drive 4. Starts Chrome with Browser Use profile 5. Connects via CDP (Chrome DevTools Protocol) 6. Runs Browser Use agent for external application sites 7. Terminates Chrome completely 8. Returns JSON result via stdout

    Prompts (prompt.py)

    • APPLICATION_TASK_PROMPT - LinkedIn Easy Apply instructions
    • GOOGLE_JOBS_PROMPT - Google Jobs/external site instructions
    • PERSONAL_INFO - Consistent personal data for forms
    • Key instructions:
    • Skip photo upload fields
    • Handle Enter key clearing text fields
    • Use Gmail verification when needed
    • Update database after completion
    • Navigate through Google Jobs to external sites
    • Handle various application portal formats

    🔧 Configuration

    Browser Setup (in linkedin_submitter.py)

    # Browser Use profile path (hardcoded for consistency)
'~/.config/browseruse/profiles/default-google-chrome'

# Chrome startup command
chrome_cmd = [
    '/opt/google/chrome/google-chrome',
    '--user-data-dir=' + profile_path,
    '--remote-debugging-port=9222',
    '--no-first-run',
    '--no-default-browser-check'
]

# CDP connection
BrowserSession(
    connection_method="connect_via_cdp", 
    cdp_url="http://127.0.0.1:9222"
)

    Subprocess Settings

    # Python interpreter
python_path = "/home/dave/miniconda3/envs/adk/bin/python"

# Timeout per job
timeout = 300  # 5 minutes

# Cooldown between jobs
await asyncio.sleep(30)

    📊 Database Integration

    Key Functions Used:

    • reserve_job_for_application() - Atomically reserves a job
    • update_job_status_applied() - Updates final status with date/reason
    • release_job_reservation() - Releases job if error occurs
    • update_job_local_file_paths() - Stores downloaded file paths
    • get_jobs_by_status() - Retrieves jobs for processing

    Status Flow:

    1. Ready To Apply - Job has resume/cover letter, ready for submission
    2. Application in Progress - Currently being processed
    3. Applied - Successfully submitted
    4. Error - Failed due to technical issues
    5. Not a Fit - Rejected by content validation

    Key Testing Points

    • Chrome starts and connects via CDP

    • Chrome fully terminates after each job
    • No 429 rate limiting errors
    • Logs appear in real-time and save to files

    🚨 Important Notes

    1. Browser Use Profile: Uses ~/.config/browseruse/profiles/default-google-chrome (NOT personal Chrome profile)
    2. Chrome Termination: Each job terminates Chrome completely to prevent 429 errors
    3. Subprocess Isolation: Each job runs in separate Python process for clean state
    4. Real-time Logs: Subprocess output streams to console while also saving to log files
    5. CDP Connection: Connects to existing Chrome instance instead of Browser Use spawning it
    6. No Process Management in ADK: Chrome lifecycle handled by subprocess exit, not ADK
    7. Shared Browser Actions: Both submitters use consolidated actions from browser_actions/shared_browser_actions.py
    8. Platform Support: Supports jobs from LinkedIn, Indeed, Glassdoor, ZipRecruiter, and Google Jobs

    Common Issues

    Chrome Won't Start

    # Check if port 9222 is already in use
lsof -i :9222

# Kill orphaned Chrome
pkill -f 'remote-debugging-port=9222'

    429 Rate Limiting

    • Ensure Chrome terminates between jobs
    • Check subprocess is exiting cleanly
    • Verify 30-second cooldowns are working

    Browser Use Profile Issues

    # Verify profile exists
ls ~/.config/browseruse/profiles/default-google-chrome

# Test profile manually
/opt/google/chrome/google-chrome \
  --user-data-dir="$HOME/.config/browseruse/profiles/default-google-chrome"

    Subprocess Failures

    • Check JSON parsing in stdout
    • Verify exit codes (0=success, 1=failure)
    • Look for Python tracebacks in console output
